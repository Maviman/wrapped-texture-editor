## Decisions where the plan was open or in tension

1. **G4: "Texture sets" keeps its name.** The four buttons measure 259.4 pt headless (41 / 47 / 87 / 60 pt wide with
   spacing) and 229.4 pt in the real window, of 283 pt of content width at 300 pt. `upper_tabs_show_one_page_each`
   checks one row, inside the upper group, no button past the panel, at 1280x800, 900x600 and 640x480.
2. **The upper pages' scroll bars lie over the content (`floating_allocated_width = 0`).** With the thin style's 6 pt
   reservation the `text` and `text_tab` scenarios ended with a 306 / 312 pt side panel (the 3D view moved, their
   asserts failed): egui reserves a bar's room only from the frame after it first shows it while the option grids keep
   their column widths from the frame before, so a page that starts to overflow grows the panel by 6 pt, and egui keeps
   a side panel's width. In the old layout the tool options area was short and practically always overflowing, so the
   bar never toggled; the taller Tool page now fits or overflows depending on the lower tab, the tool and the
   selection. I first tried `ScrollBarVisibility::AlwaysVisible` on the Tool page (fixes it too) but that draws a
   permanent track on pages that do not scroll. The overlay bar is still visible (2 pt, 10 pt when hovered) while a
   page overflows. Regression test: `text_panel_tests::the_side_panel_keeps_its_width_when_the_tool_page_starts_to_scroll`
   (fails with the 6 pt reservation: 306 pt). The lower group's scroll areas (Brush / Text tabs, Layers list) keep
   the old style, as the plan keeps that group unchanged; the same toggle is possible there in principle (it was before
   this branch too) — not seen in any test or scenario.
3. **The text focus rule.** Plan 6.4 exception 1 (`focus_text_content` sets `upper_tab = Tool`) is applied only while
   the tool is Text; a request left over from another tool is dropped there without a tab change (the Tool page would
   drop it too, but it may not be shown). Plan 8.3 step 5 says "Text tool click in the view (places a text) → Tool";
   placing a text does not ask for the focus in this app (only a click with no text typed does, "Type the text in the
   tool options first"), so `side_tabs` checks the focus request with an empty draft, and that placing a text keeps the
   shown tab (the "tool change never moves the upper tab" intent).
4. **`upper_keep` uses the Color page height measured when it was last shown** (first guess
   `COLOR_FIXED_HEIGHT_GUESS + 140` = 284 pt, the headless measurement 283.5 pt; the real window measures 289.5 pt).
   The measured heights survive a document change (they do not depend on the document), so the split does not jump
   when a project is opened. `the_colour_page_guess_matches_its_measured_height` keeps the guess honest.
5. **`BRUSH_OPTIONS_HEIGHT` stays 144.** Re-measured: the header-less Tool page with the Brush is 135 pt (55..190 in
   the real window), so 144 still covers it with slack.
6. **Double-click on the objects list.** egui counts two quick clicks anywhere as a double-click; a plain double-click
   only frames when the click before was on the same row (`ObjectsTabState::last_click`), so a quick Ctrl- or
   Shift-click on another row stays a click.
7. **Reveal is served when the Objects page is drawn**, so a pick made while another tab is shown scrolls the row into
   view when the user opens the Objects tab.
8. **`Harness::in_row` (control_sweep.rs)** now keeps only the widgets whose centres lie nearest the label's line: with
   the Text tab below a long Tool page, AccessKit also lists the Tool page's clipped widgets behind the Text tab's rows
   (the sweep `every_text_control_changes_exactly_its_own_field` clicked a hidden "Flip X" / "Occlusion" checkbox for
   "Other side").
9. **`control_sweep::apply_actions`** applies the object actions through `object_ops`, so the Objects tab tests see
   their effect.
10. **`texture_sets.rs` was CRLF in the repository** (one of a few files); it is LF now (most of it was rewritten
    anyway). `view/view3d.rs` (CRLF) kept its line endings.
