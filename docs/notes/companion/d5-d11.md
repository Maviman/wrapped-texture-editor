## D5 capture + hooks

- `app.rs`: `raw_input_hook` -> `companion.inject` between the pen records and `pen.route`; `logic` ->
  `companion.logic` after the jobs and before the self-test tick. `WteApp::new` restarts links left on (interactive only).
- Poller decision (plan 2.2): the cross-thread poller works; no fallback needed. The self-test's own capture and the
  companion's share a frame without trouble (both scenarios take mid-run shots while streaming).
- Measurements (this machine, RTX 5070, 144 Hz monitor, release exe):
  - Capture request -> pixels: mean 17.3 ms / max 29.9 ms at 1280x800 (`companion`), mean 20.4-20.9 ms / max 27-46 ms
    at 1920x1080 (`companion` and `companion_host` + `host_probe.py --hold 8`). One display frame, as expected (the
    capture is of the frame after the request).
  - Frame time at 1920x1080 (`frame_profile`, `target/companion/d5/budget.log`): without a session 6.97 ms average
    (vsync), ui cpu 0.5 ms; while streaming at about 30 captures/s with the pen hovering at 60 Hz: still 6.97 ms average,
    max 8.1-9.7 ms, ui cpu 1.5 ms. The capture's own GPU work (blit + copy) runs in egui-wgpu's paint, which
    `frame_profile` does not time separately; the frame interval never left the vsync slot, so the added cost per
    captured frame is below the frame slack (< 5 ms) here. The plan's "<= 2 ms per captured frame" could not be isolated
    more precisely without patching egui-wgpu; the 10 % mouse-stroke comparison with a tablet connected is left to the
    gate (it needs a mouse stroke while a session streams).
  - Encoding / link: `companion` scenario 63 frames, 1.69 MB for about 3 s of activity at 1280x800 (USB profile).
- Idle: in an interactive run an idle app paints no frames, so nothing is captured. In a self-test run the runner
  repaints every frame, so captures continue at the fps cap, but the encoder finds no changed cell and sends nothing
  (no FRAME unless the input sequence advanced), which is the "no frames after the refine" rule on the wire.

## D6 input

`Companion::inject` drains the hub (input of the current session only; an `Ended` stops the drain so a new session's
input waits a frame), returns without touching the frame when there is no session, else runs `InputStage::process`.
ACTION Undo / Redo wait in `logic` until the tools are idle, then go through `dispatch`. Focus: `raw.focused = true`
and `WindowFocused(false)` dropped while the remote is active or sent input in the last 5 s. Tests:
`companion::tests::a_session_end_in_mid_stroke_releases_the_pen` (real loopback session, pulled connection, the router
sees the release) and `no_server_or_no_session_leaves_the_frame_untouched`, plus the `input` tests.
