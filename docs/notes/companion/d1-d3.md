# D1-D3 — crypto, protocol, fixtures, auth, prefs, encode_jpeg, encoder

Desktop builder. One commit for the three steps (they were built and tested together).

## D1 crypto + protocol + fixtures

- `crates/wte_app/src/companion/crypto.rs`: SHA-256 (streaming), HMAC-SHA256 with the padded key absorbed once
  (`HmacKey`, so PBKDF2 costs two compressions per iteration: 100,000 iterations take well under a second even in the
  unoptimized test build), PBKDF2-HMAC-SHA256, `ct_eq`, hex, the Crockford code (`code_from_bytes`, `normalize_code`,
  `display_code`), `random_bytes` (`BCryptGenRandom` with `BCRYPT_USE_SYSTEM_PREFERRED_RNG`, `raw-dylib` bcrypt; no
  crate).
- Test vectors (SHA-256 "", "abc", the 448-bit FIPS message, 1,000,000 x "a" fed in uneven pieces; HMAC RFC 4231 cases
  1, 2, 3, 6; PBKDF2 "password"/"salt" 1, 2, 4096 and the 40-byte RFC 7914-style case) were printed by Python
  `hashlib` / `hmac` on this machine and pasted, not typed from memory.
- `proto.rs`: every message of spec 4.3-4.5 (`Msg`), `encode` / `decode`, `FrameReader` (any split, `TooLong` above the
  direction's limit), the key table of 4.8 (`KEY_TABLE`, 74 codes), `mods` <-> `egui::Modifiers` (Ctrl sets `ctrl` and
  `command`, as egui-winit does on Windows, so the app's `COMMAND` shortcuts match).
- Fixtures `docs/protocol/fixtures/v1/*.hex` (22 message types; one line of lower-case hex + LF) and `handshake.json`
  are written by the Rust tests with `WTE_WRITE_FIXTURES=1` and checked otherwise (decode -> re-encode byte for byte,
  decoded value == the sample). The FRAME fixture carries two real 16x16 JPEG tiles (red, blue) so a client test can
  draw it; its check decodes both tiles instead of comparing JPEG bytes (they depend on the encoder version).
- `tools/companion/check_handshake.py` (`python -E -P`) recomputes transcript, salt, PBKDF2 pair key, token and both MAC
  pairs with `hashlib` / `hmac`, and checks every fixture's header: "handshake.json and 22 fixtures: OK".
- `wte_core::encode_jpeg` was added here (planned for D3) because the FRAME fixture needs it.

## D2 auth + prefs

- `auth.rs`: `negotiate` (highest common major version; `PROTO_MIN_SUPPORTED` = 1), `transcript`, `pair_salt`,
  `pair_key`, `token_from_pair_key`, `client_mac` / `server_mac`, `PairingWindow` (code per dialog opening, replaced
  after 10 min, after 5 failures a new code and 30 s TOO_MANY_ATTEMPTS; `fixed` for the test code), `offered_modes`,
  `Handshake::start` / `check` / `confirmed`, `client_auth` (the test client's side), `PairedTablet`.
- Decision: BUSY (another tablet is connected) is answered at HELLO time by the server (it knows the tablet id there), so
  a second tablet never raises an Allow prompt. A HELLO for which no mode is available gets PAIRING_CLOSED (or
  TOO_MANY_ATTEMPTS while the lockout lasts).
- Prefs: `Prefs::companion: CompanionPrefs` (`state.rs`, `#[serde(default)]`, lenient: an entry that does not read is
  the default), `FingerMode`; `prefs::sanitize_companion` (port 0 -> 47800, a desktop id that is not 32 hex digits is
  made again, paired records whose id / token do not read are dropped). Old preference files load with all links off.

## D3 encoder

- `encode.rs`: `to_rgb` (box downscale 1..4, edge blocks clipped), `changed_cells` (64-px cells), `merge_cells` (row
  runs, then equal runs downwards; max 8 x 8 cells), `encode_tiles` (scoped threads, `min(4, cores - 2)`), `Encoder`
  (KEY on first frame / size / scale change / `need_key`; empty FRAME only when the input sequence advanced; refine after
  400 ms of no change for cells below the refine quality), `profile` / `apply_config`, `RateController` (3 slow acks
  -> step down: quality -15 to 40, then den +1 to 4, then fps / 2 to 4; fast for 2 s -> one step up, never above the
  ceiling).
- The last-sent reference is the source picture (not the JPEG-decoded one): the diff compares source with source, so
  JPEG noise never makes cells "change".
