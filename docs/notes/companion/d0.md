## Verify items

### Fact 10 — minimized window

`REG\eframe-0.37.0\src\native\wgpu_integration.rs:997-1019`: a `Resized` with a zero side (winit's minimize signal on
Windows) is not passed to the painter (`NonZeroU32::new` fails). The surface therefore keeps the size it had before
the window was minimized (`surface_state.width/height` are the last non-zero size), and a capture requested while
minimized would render the stale layout at the old size (the "zero-sized surface" warning only fires for a surface
that was never configured). Consequence, as planned: the companion does not capture while
`ViewportInfo::minimized == Some(true)`; STATE gets `NO_PICTURE` and the tablet keeps its last picture. On restore the
next capture is a KEY frame.

### Plan 5.3 — Secondary press + release in a view

No context menu is attached to the 3D or 2D view (`grep context_menu|secondary_clicked` over `view/` and `tools/`: none;
`tools/mod.rs:421-426` maps Secondary to orbit/pan only). A Secondary press and release without motion does nothing in
a view. The 6-point travel threshold is kept anyway (a tap must not start an orbit that moves the camera by a pixel).

### Plan 5.5 — `RawInput::focused == false`

`REG\egui-0.37.0\src\response.rs:406`: `Response::has_focus()` is `i.focused && mem.has_focus(id)`; with `focused`
false, a focused text field reports no focus (its text cursor is not painted: `widgets\text_edit\builder.rs:1015`), and
`ctx.text_edit_focused()` still reports the memory focus. The self-test sets `focused = true` for the same reason. The
companion forces `focused = true` while a session streams and remote input arrived in the last 5 s, and removes
`WindowFocused(false)` events then (plan 5.5).

### wgpu `device.poll` from a second thread

`wgpu::Device` is `Clone + Send + Sync` (`REG\wgpu-30.0.1\src\api\device.rs:19`); wgpu-core's poll takes its own locks.
The capture callback (`REG\egui-wgpu-0.37.0\src\capture.rs:211-247`) runs on whichever thread polls. Several screenshot
callbacks of one frame are served by one capture (`capture.rs` "for callback in callbacks"), so the self-test's own
capture and the companion's capture can share a frame. The decision between the poller thread and the logic-poll
fallback is made by measurement in D5 (`docs/notes/companion/capture.md`).
